# Как выпустить обновление для всех пользователей

## Обычный выпуск через GitHub

1. Внесите изменения в `main` и увеличьте `VERSION` в `cubedesk/__init__.py`, например с `1.6.0` до `1.6.1`.
2. Обновите `CHANGELOG.md`. Если менялась прошивка, отдельно увеличьте её `version` и `build_id` в `firmware/version.json`. Если прошивка не менялась, её номер оставьте прежним.
3. Откройте **Actions → Build and release CubeDesk → Run workflow**, выберите `main`.
4. Сборка проверит тесты, соберёт `.exe` и универсальную прошивку, создаст манифест с SHA-256 и сначала загрузит файлы в черновик релиза.
5. После успешной загрузки релиз публикуется. Тег `vX.Y.Z` создаётся автоматически из версии приложения. Пользователи увидят обновление при следующей проверке в панели.

Также поддерживаются push тега `vX.Y.Z` и публикация релиза через интерфейс GitHub. Номер тега должен соответствовать версии приложения в его исходниках. У уже опубликованного полного релиза файлы этим сценарием повторно не заменяются: исправление выпускайте под новым номером.

Доступ используется через временный `GITHUB_TOKEN` внутри Actions с правом записи в этот репозиторий. Личные токены в исходниках, пользовательском приложении и файлах релиза не нужны.

## Что видит пользователь

CubeDesk обращается только к публичному GitHub Releases этого репозитория. Локальные настройки и ключ кубика в GitHub не отправляются. Проверка выполняется при запуске приложения и раз в час, установка — по кнопке.

`update.json` связывает номер релиза, версии приложения и прошивки, аппаратную модель, точные имена файлов, размеры и SHA-256. Загрузки ограничены по размеру и времени. При ошибке проверки текущая программа и кубик не изменяются. Это проверка целостности через HTTPS и доверенный репозиторий; коммерческой подписи Authenticode у `.exe` нет.

Установщик Windows сохраняет предыдущий файл рядом с приложением как `.previous`, проверяет запуск новой версии по локальному health endpoint и откатывается при неудаче. Библиотека и настройки хранятся отдельно в `%LOCALAPPDATA%\CubeDesk`. Если каталог программы недоступен для записи, установка завершается до остановки текущего воспроизведения.

Обновление прошивки — отдельное явное действие для совместимого HelloCubic-Lite с PCStream 1.6+. При тайм-ауте запись автоматически не повторяется: панель проверяет возвращение кубика и версию. Файловая система и конфигурация не стираются.

## Локальная сборка

```powershell
python -m pip install -r requirements-build.txt
python -m unittest discover -s tests -v
python build_app.py
python -m platformio run -d firmware
python package_firmware.py
python release.py
```

Для публикации подготовленных файлов через CLI нужен `gh` с авторизацией владельца: `python publish_release.py`. На обычном пользовательском ПК авторизация GitHub не требуется.

Публикуйте **только содержимое `dist/release`**. В других папках `dist` могут находиться частные сборки, диагностические отчёты или старые тестовые файлы.
